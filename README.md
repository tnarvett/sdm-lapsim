# SDM Lap Optimizer

FSAE lap simulator + track editor + FEA/CFD export generator, running as a real
desktop app (own window, no browser chrome, no manual server) built with
[pywebview](https://pywebview.flet.dev/) around a single self-contained HTML/JS
app. Built with Claude Code, Sept 2026. Related to the Python repo at
`../SDM-Lap-Optimizer` (that repo has the real CasADi/IPOPT solver; this app does
NOT -- it runs a fast quasi-steady-state solver in JS).

## Download and run (Windows)

Grab **`SDM-Lap-Optimizer.exe`** from this repo's
[Releases](../../releases/latest) page and double-click it. That's it -- no
install, no Python, no browser. It opens its own window (Edge WebView2, which
ships with Windows 10 2004+/11; older Windows gets a one-time prompt to install
it). Everything -- your vehicle setup, edited tracks, solved laps -- is saved
locally in that window's storage and is there next time you open it.

Exports (Step 4) download to your normal Downloads folder exactly like they
would from a browser, because the window *is* a real browser engine, not a
sandboxed preview.

## Run from source / build it yourself

```bash
git clone <this repo>
cd sdm-lapsim-webapp
pip install -r requirements.txt
python app.py          # runs the app in a window, no build needed
python build.py         # -> dist/SDM-Lap-Optimizer.exe (what Releases ships)
```

`app.py` just points pywebview at `lapsim.html`; `build.py` runs PyInstaller
(`--onefile --windowed`, `lapsim.html` bundled as data, `icon.ico` embedded).
The web app itself (`lapsim.html`) also still works as a plain static file if
you'd rather open it directly in a browser or serve it from any web host --
nothing about it depends on the desktop wrapper.

## Map scale calibration  (re-done Sept 2026 — the old figures were wrong)

| map | grid / label fit | scale | old (wrong) |
|---|---|---|---|
| Endurance | 100 ft = 39.69 px (26-gridline linear fit, resid 0.5 px) | **0.76793 m/px** | 0.6684 (~13% short) |
| Autocross | 100 ft = 45.92 px (17 axis-label fit, resid 0.4 px; grid cell = 25 ft) | **0.66448 m/px** | 0.5507 (~19% short) |

The old calibration measured the wrong pixel span; every pre-Sept-2026 lap distance
was short by those factors. Grid is square and near-distortion-free on both maps.

| event | length | Quick (1.2 m mesh) | Refined (0.6 m mesh, aero-coupled) |
|---|---|---|---|
| acceleration | 75 m | ~4.4 s | -- |
| skid pad | R 9.125 m | ~5.3 s / circle, 1.31 g | analytic, same both modes |

Autocross length barely moved from the pre-rescale trace (the old hand-trace ran
long in px, cancelling the scale error); endurance grew ~25% once the scale was
fixed, cutting the lap count from 13 to 10. Quick's mesh was tightened from 2.0 m to
1.2 m (Sept 2026) because 2.0 m skipped the tightest hairpins outright -- Quick and
Refined now agree to within a few percent instead of ~15%.

## Grip model (reworked Sept 2026)

The corner-speed / accel / brake passes now run through `gripAccel()`, which adds
lateral- and longitudinal load-transfer degradation on top of the load-sensitive
tyre model: shifting weight onto the loaded tyres returns less combined grip than a
flat "mu * mg" 4-wheel model, because mu falls off with load. RWD traction also now
credits the rearward weight transfer under acceleration (previously ignored, which
made launches pessimistic). Defaults changed: `mu_load_sens` 0.12 -> **0.20** (matches
published FSAE-tyre load sensitivity far better than 0.12 did) and a new **`grip_factor`**
(Tyres panel, default **0.95**) representing the usual gap between theoretical and
achieved grip (temperature, surface, driver). Net effect at the same mu0 = 1.35:
peak lateral ~2.0 g -> ~1.7-1.9 g, peak tyre-braking ~2.1 g -> ~1.5-1.9 g, all now in
FSAE-realistic ranges (previously optimistic by ~15-20%).

**Peak braking is now reported as two numbers**, because the old single figure
conflated tyre grip with aero drag: **Peak braking (tyre)** is `Fbrake/m` (the brake
sizing case -- what the brakes must be able to lock), while **Peak decel (total)**
also includes aero drag + rolling resistance (what an accelerometer actually reads,
~0.3-0.4 g higher at top speed). Same split in `brake_model.csv` and the manifest
(`peak_decel_g_tyre` vs `peak_decel_g_total`).

The endurance/autocross curvature clamp was also tightened from a 1.5 m floor to
**3.5 m** -- FSAE's 9 m-outside-diameter hairpin minimum, at the 3.5 m minimum
course width, puts the tightest legal centreline radius right there, so anything
tighter in a traced line is an extraction artifact, not a real corner.

## Exports (Step 4)

Every export is a real downloadable file. **Download** saves the one on screen;
**Download all** builds a single `sdm_export_<track>_<event>.zip` (self-contained
STORE-zip writer, no library). Downloads work when the app is served locally; inside
the published artifact the sandbox blocks them, so use **Copy** there.

| export | file | what |
|---|---|---|
| Motion | `motion.csv` | just `t_s, v_ms, v_kmh, a_long_ms2, a_long_g` — a bare speed/accel trace |
| Telemetry (full) | `telemetry.csv` | s, t, v, a_long, a_lat, steer, kappa |
| **Brake model pack** | `brake_model.csv` | `#`-commented header (all vehicle + brake-system params, per-lap braking summary, hardest single stop, full-event energy over N laps) then a 36-column per-station timeseries: axle/corner brake force & power, rotor torque, pad clamp force, wheel ω / rotor rpm, pad sliding speed, per-rotor heat flux, corner Fz, convective h, pedal-force estimate. Read with `pd.read_csv('brake_model.csv', comment='#')`. |
| Track geometry | `track_geometry.csv` | s, x, y, curvature, half-widths |
| Brake duty cycle | `brake_duty_cycle.csv` | the older brake table (kept; `brake_model.csv` supersets it) |
| Structural / Thermal / CFD | `*.csv` | first-order estimates, flagged in the manifest |
| Manifest | `manifest.txt` | provenance + summary |

Brake-model derivations: per-corner heat power = `F_corner * v`; rotor torque =
`F_corner * tire_radius`; pad clamp = `T_rotor / (2 * pad_mu * r_eff)`; swept area =
`pi*(ro^2 - ri^2)*2` (both faces); `h = 30 + 4.2*v^0.8`. Energy sums are validated
against the solver's own `brake_energy` (they match to the kJ).

## Bugs fixed Sept 2026 (found during a full data + UI audit)

- **The header/footer "lap" readout could get stuck on "needs solve" forever after
  a real, successful solve.** Cause: `renderResults()` unconditionally drew the
  Results-page canvases (`drawTrackMap`, `drawG`, `drawGG`, ...) even while that page
  was hidden (e.g. solving from the Run page -- the normal workflow). A hidden
  canvas reports 0x0, which sent `drawGG`'s ring radius negative and
  `ctx.arc()` threw `IndexSizeError` -- silently aborting `runSolve()` before it
  reached `refreshLap()`/`renderStatus()`. Fixed two ways: `renderResults()` now
  skips its paint while the Results view is hidden (it's correctly repainted by
  `go()` when you navigate there), and `setupCv()` floors canvas w/h at 80 px so no
  draw function can compute a negative dimension from a collapsed canvas again.
- **Table text was unreadable** (dark grey on dark background) on the Corner report
  and Telemetry tables. Root cause was an unrelated browser extension injecting
  Tailwind/Material-style CSS that overrode `<table>` text color; fixed by having
  `table.data` set `color: var(--text)` explicitly instead of relying on inheritance,
  which is more robust against exactly this kind of external CSS intrusion.
- **Imported tracks (OptimumLap CSV / cone CSV / GPS) had no delete affordance** --
  they don't fork with `source: "user"` like an edited copy does, so the old
  `source !== "user"` guard silently excluded them from both the "My tracks" list
  and `deleteTrack()`. They now show in My tracks (tagged read-only) and can be
  deleted; only the 4 locked FSAE presets (`presetFor` set) are protected now.
- **Character encoding**: the file had no `<meta charset>` (it's designed to be
  artifact-wrapped, which normally supplies one) and a few UTF-8 em-dashes/degree
  signs/etc, so serving it raw (e.g. `python -m http.server`) let the browser guess
  wrong and mojibake half the UI. Added `<meta charset="utf-8">` as the first line
  and converted the handful of non-ASCII characters in JS strings/CSV headers to
  plain ASCII, so it renders correctly regardless of how it's served.
- **`structural_load_cases.csv` brake torque was ~2.4x too low** (used the pad
  effective radius instead of the tyre rolling radius to convert contact-patch
  force to wheel torque) and **pedal force was ~3x too high** (ignored the
  caliper/master-cylinder hydraulic ratio entirely, ~2000 N instead of ~600 N).
  Both fixed; a `brake_hyd_ratio` param (default 6.0) was added to the Brakes panel
  for the pedal-force calc, shared with `brake_model.csv`.
- Autocross's headline **"Min speed"** was always 0.0 km/h (the standing-start line),
  not the slowest corner. `vMin` now skips the first ~15 m on open events.

## Known issues / next steps

- **Endurance trace soft spots** (source is only 1024 px wide, drawn line ~2 px):
  the bottom serpentine and the two thin-loop chicane markings carry ~2-4 m of
  lateral jitter; a few sub-5 m curvature spikes survive the de-kink pass. The
  pit-lane island by start-finish is masked (`EN_PIT_BOX` in `extract_tracks.py`).
  A genuinely tight trace needs the map re-exported at >= 4000 px (ideally the PDF).
- QSS solver: no transient yaw dynamics, no tyre thermal model, driver assumed
  perfect. Even with the Sept 2026 grip-model fixes, lap time is still optimistic
  by roughly 5-12% vs a real car -- that's inherent to steady-state QSS, not a bug,
  and is stated in the manifest export. Structural/thermal/CFD exports are
  first-order estimates for sizing screens / CFD case selection, not validated loads.
- Vehicle defaults: mu0 1.35, load-sensitivity k 0.20, grip utilisation 0.95, ClA 2.4,
  CdA 1.30, 52 kW. Tune on the Vehicle panel; they're editable and persisted to
  localStorage. If your real data (brake pressure, GPS speed, MoTeC g's) disagrees,
  `mu0` / `grip_factor` are the two knobs to recalibrate against it.
